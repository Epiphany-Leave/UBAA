# 手机生命周期修复与下一轮缓存任务

## 2026-09-22 本轮修复

- 根因：宿主将普通 paused/resumed 当作后端失效，调用 rebuildBackend，清除身份和功能快照并重新初始化。现在普通切后台保留现有 controller/backend；只有 detached 后恢复才保留原有恢复流程。系统真正杀掉进程后的冷启动不属于内存保留。
- 根因：主界面用状态切换子页面，没有向 Android 系统返回注册拦截。现在通过 PopScope 复用标题栏返回逻辑。子页逐层返回，根页面允许系统离开。待确认写操作先取消，提交中不允许返回触发重复提交或隐藏结果。
- 回归：连续三次后台/前台不创建新 backend、不重复读取功能；子页面与功能页系统返回；写确认返回只取消、提交中不取消。宿主 21 项和本轮相关 UI 11 项通过；保留 detached 恢复测试。
- 用户提供：校外自动路线选择 direct 时，希冀和课堂签到 network_error；显式 WebVPN 后均正常返回暂无数据。这是校外路线可达性证据，不是非空业务数据已经验收。暂不修改学校协议或跨身份回退。

## 当前交付边界

本轮只交付 `output/arm64/UBAA2-arm64-release-lifecycle-fix.apk`。请验证登录后反复按 Home/切回，以及图书馆等多级页面的系统返回手势。主界面根层返回离开属于正常行为。真实进程被系统回收后，仍执行冷启动；不能保证手机永不杀后台。

## 下一轮：首次本地化与手动刷新

生命周期修复交付时仅保留存活进程内数据。后续已实现成绩、考试、学期和作业清单的 Core 持久缓存，并在 Pixel 8 通过用户首轮验证；[最新实现与边界](evidence/2026-09-22-cache-signin.md)。以下保留原缓存规划，课程资料/历史预约等其他快照未全部实现；启动仍校验会话，不宣称完整离线登录。

1. 先做成绩、考试、作业清单和课程资料的只读快照：首次访问无缓存时查询，成功后保存；后续优先本地，用户手动刷新，显示数据时间；刷新失败保留旧数据并标记失败。换日期/学期等查询条件时使用独立缓存键，不能误用上一条件的数据。
2. 存储、版本及归属判断放在 Rust Core，经 facade/bridge 使用；按账号、已确认本科/研究生身份、功能和查询条件隔离。切换账号、退出登录及清除账号不能显示其他账号数据；旧请求不得写入新账号缓存。采用现有私有文件/原子写入方式。
3. 预约余量、可签到状态、报名资格和所有写入前确认仍实时校验；不能把离线快照作为执行预约/签到的权限。历史预约和历史打卡可作为明确标注时间的浏览快照。
4. 冷启动先恢复可用本地展示，避免全模块并发刷新；按用户进入功能再加载缺失数据。不要用永久缓存掩盖新增作业、考试变更，保留显眼手动刷新与更新时间。
5. 分开验证正常切后台、强杀重开、断网重开、账号切换、刷新失败、更新后的空结果、旧请求晚到、本科/研究生隔离。每轮一个 APK，由用户实测后再扩大范围。

另行待查：自动路线当前优先 direct，校外业务域不可达时的处理策略。不得因网络问题改动身份分流或盲目重复执行业务写请求。
