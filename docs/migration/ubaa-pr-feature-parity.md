# UBAA-PR 功能迁移矩阵

旧版 UBAA-PR 是用户可见行为与交互的基准。本表区分“已有协议/API”和“用户可以像旧版一样使用”；只有后一项通过目标设备验收才标记完成。

| 领域 | UBAA2 当前状态 | 下一步 | 完成条件 |
|---|---|---|---|
| 启动、图标、登录与会话 | 启动修复和旧版图标已构建；登录与路线逻辑已存在 | Pixel 8 安装并验证进入登录页、Direct/WebVPN 登录和注销 | 用户完成真实只读验证 |
| 课表 | 已有 GSMIS 正式已选课、按账号整学期缓存、手动更新、学期/周切换、完整时间轴、跟手换周和课程详情 | 验证真实更新、断网重启、账号切换；迁移 Android 桌面组件 | Pixel 8 的真实课表与离线场景通过，三类组件可用 |
| 首页与待办 | 功能目录和本地今日课程存在 | 迁移旧版待办聚合、逐项失败提示和刷新状态 | 首页能显示与旧版等价的今日课程和待办反馈 |

| 设置、账户、公告与诊断 | 基本个人页、路线与诊断入口存在 | 对齐旧版设置、版本、公告和错误展示 | 常用设置与错误恢复路径可用 |

## 工作顺序

1. 建立可运行基线：Pixel 8 验证启动、登录、注销，以及已迁课表的更新和离线浏览。
2. 完成课表的 Android 桌面组件：周课表、今日课程、近日课程，支持缩放、切周和点击进入课表。
3. 迁移首页、成绩、考试、空教室的专用页面；补齐研究生非空数据的解析证据。
4. 按使用频率迁移博雅、图书馆、SPOC、希冀、签到、场馆、打卡和评教的专用工作流。
5. 收尾设置、公告、错误反馈、跨平台适配，并逐项完成真实设备验收。

## 验收原则

- Fixture、Mock、单元测试和无签名构建只证明确定性实现，不替代真实学校账号或 Android 页面验证。
- 真实读取与真实写入分开；写入始终需要用户在应用内主动确认，且另行取得授权。
- 不重新实现已有 Rust facade、Bridge 或缓存逻辑；页面迁移复用现有链路。
